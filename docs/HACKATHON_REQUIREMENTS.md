**Verified against official public sources on 27 September 2026.** Research was read-only: no form answers were entered or submitted. This document records the live form and published guidance, not a completed entry or confirmation of Njia's registration.

## 1. Immediate conclusions

- **Submit by Sunday 27 September 2026, 19:30 Kenya time (EAT, UTC+3)** = **17:30 Tunis (UTC+1)** = **16:30 UTC**. The event's 20:00 Tunis closing time is not the submission deadline. [S1, S2]
- Submit **once per team or solo project through the official Google Form**, using the same final team name and lead email as Final Team Confirmation. A repository push alone is not submission. [S1, S2]
- The live form has **20 required questions**, including **three required URLs: source code, presentation, and a 90-second demo video**. It requests links, not file uploads. [S2]
- A **working prototype or interactive demonstration is required**. **Public deployment and Docker are explicitly optional**. A local app demonstrated in the video with run instructions is accepted by the published guide. [S1, submission checklist and FAQ]
- **Kenya participates**, with Nairobi Hackerspace and confirmed online participation routes. Solo entrants and teams of up to five are accepted; actual registration/attendance must already be confirmed. Final Team Confirmation is closed because capacity was reached. [S1, S2, S4]
- **Click Mobile's KSh 50,000 is the total cash prize contribution for Kenya.** The number of recipients, split, and amount for any individual winner are **not announced**. It is separate from the country podium. [S1, S2, S3, S6]
- Recommended Njia primary preference: **Brightest GmbH — Skills & Employability Award**. Consider Click Mobile if the team is confirmed for Kenya and can demonstrate the mobile-first Kenyan use case; Artefact is explicitly open to all participating countries. These are fit recommendations, not eligibility approvals. [S1–S3; local project evidence below]

## 7. Published judging rubric and Njia evidence

Country judging uses submitted materials and the same **100-point** rubric. [S1–S3]

| Criterion | Points | Official emphasis | Njia evidence to show (recommendation) |
| --- | ---: | --- | --- |
| Problem + user value | 20 | Clear need, credible user, practical value or meaningful delight | Kenyan job seeker moving from self-reported skills to a specific learning action |
| Functional execution | 20 | Core experience works live, beyond a static concept | Skill confirmation → gap analysis → four-week plan → practice check → report |
| Quality of AI use | 20 | Quality/relevance of actual AI; explain models/tools/workflows; provider-neutral | Accurately distinguish rule extraction, TF-IDF retrieval, curated plans, development AI assistance, and optional unverified-live Ollama |
| Testing + reliability | 15 | Tests, failure modes, cost, speed, fallbacks | Existing test artifacts, small-sample fallback, manual skills route, model-failure fallback; label synthetic evaluation limitations |
| Experience + demo | 15 | Understandable, usable, clear 90-second demonstration | Rehearsed end-to-end walkthrough and mobile-width evidence |
| Responsible AI + data | 10 | Privacy, consent, bias, safety, copyright, human oversight | Local processing consent, editable skill chips, historical-data disclosure, no employment-probability/certification claims |

The guide explicitly permits conventional software and says to state honestly if no AI was used; the AI-use score still assesses the actual demonstrated contribution. **No generative-model requirement is published**, but tool neutrality does not promise equal AI-use scores for different implementations. The current Njia docs say the default runtime has no generative model or hosted inference and optional Ollama was not installed/live-tested. Do not present that optional path as demonstrated AI.
