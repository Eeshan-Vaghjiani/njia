UNDER THE HOOD

Evidence first.
Clear about the AI.

1. Confirm your skills. Upload a PDF, DOCX or TXT (up to 4,000,000 bytes) with consent, or paste text. Review the preview before finding skills. Server-side keyword matching recognizes dataset skills and common aliases; it can miss context, so you confirm the result.

2. Understand local demand. We count the top 15 skills for your role and market. Below 50 local postings, we use the 10-country sample and show that explicitly.

3. Make a plan. Curated exercises and resources are always available. A configured Ollama or Groq model can rewrite the coaching. Remote AI requires a separate opt-in to send only structured skill and curriculum data, never your CV. Leave it unchecked for a curated plan. The result labels which method actually ran.

4. Practice. Three fixed questions use an answer key. A reflection is for self-review, not automatically graded or certified.

Job retrieval: TF-IDF and cosine similarity find historical examples related to your skills. This is classical information retrieval, not a generative model.

Privacy: No CV storage. Uploaded files and pasted text are processed in server memory, including on a public deployment. CV never sent to AI. Basic email, phone, link, and labelled identity redaction is best-effort; review the preview. No database, analytics, or browser persistence. Your preview and session results stay in page memory until cleared or the page is closed. Reset clears the selected file too.

API: POST /api/upload accepts multipart file and consent=true, returning text, filename and a processing note. POST /api/plan accepts use_ai (default true) and ai_consent (default false). This interface sends use_ai: false for remote AI without opt-in. Explore the API documentation ↗

Data: lukebarousse/data_jobs, 2023, Apache-2.0 according to the prepared dataset documentation. Tech/data roles only; postings are not representative of all employers or workers.
